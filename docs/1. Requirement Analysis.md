# Requirement Analysis

## 1. Overview: S32K144 스마트홈 제어 임베디드 시스템

본 프로젝트는 NXP S32K144 MCU를 기반으로 한 스마트홈 제어 임베디드 시스템을 설계하는 것을 목표로 한다. 

각종 센서 입력을 수집하여 제어 로직에 따라 출력 장치를 구동하며, 사용자 인터페이스와 외부 통신을 지원한다. 특히, 시스템을 CAN 통신을 통한 외부 명령으로 제어할 수 있게하여 중앙 관제 기능을 강화한다. 

---

## 2. System Purpose

- 사용자 편의성과 보안을 강화하는 스마트홈 제어 기능 제공
- 에너지 절감과 안정성 확보
- 실시간 동작 보장 (RTOS 기반 태스크 관리)

---

## 3. Requirement Categories

### **3.1. 시스템 모드 관리**

- 시스템은 **3가지 모드**를 가진다: 1) **Monitoring**, 2) **Manual**, 3) **Security**
- **버튼**과 외부 명령을 통해 모드를 순환하며 변경할 수 있다.
- 단, **보안 경고 상태**(3.5절 참고)에서는 **버튼을 통한 모드 변경이 비활성화**되며, 오직 외부 명령을 통해서만 모드 변경 및 경고 해제가 가능하다.

### **3.2. 환경 모니터링 및 표시**

- 이 기능은 어느 모드에서나 동일하게 동작한다.
- 주기적으로 온도와 습도를 측정한다.
- 주기적으로  주변 밝기를 측정한다.
- 측정한 온습도, 밝기 값을 디스플레이에 표시한다.

### **3.3. 자동화 기능 (모니터링 모드)**

- **자동 조명 제어**: 주변 밝기 값에 반비례하여 메인 조명의 밝기를 제어한다.
- **자동 팬 제어**: 온도 값이 설정된 임계값(예: 28℃) 이상이면 팬을 동작시킨다. 임계값 미만이면 OFF 한다.

### **3.4. 장치 수동 제어 (수동 제어 모드)**

- **메인 조명 수동 제어**: 이 모드에서는 주변 밝기와 상관없이, 사용자가 수동으로 메인 조명의 밝기를 실시간으로 제어한다.
- **개별 장치 선택 및 제어**:
    - **버튼으로**는 도어락, 블라인드, 외부 전원을 순차적으로 선택하는 데 사용된다. 선택된 장치는 디스플레이에 표시된다.
    - 디스플레이는 현재 모드뿐만 아니라 수동 제어 모드일 때, 현재 선택된 장치도 표시한다.
    - 선택된 장치를 다음과 같이 제어한다.
        - **도어락**: 열림(90도) / 닫힘(0도) 상태를 토글한다.
        - **블라인드**: 정방향/역방향으로 일정 각도씩 회전시킨다.
        - **외부 전원**: ON/OFF 상태를 토글한다.

### **3.5. 보안 기능 (보안 모드)**

- 보안 모드가 활성화되면 대기 LED가 점등되어 대기 상태임을 알린다.
- 이 상태에서 범위 내 움직임을 감지하면, 시스템은 **'보안 경고 상태'**로 진입한다.
    - 일정 시간 경고음이 울린다.
    - 보안 경고 상태등이 빠르게 점멸한다.
- **보안 경고 상태**는 오직 외부 명령을 통해서만 해제할 수 있다.

### **3.6. 사용자 피드백**

- 모든 버튼 클릭 시  '삑' 소리와 함께 입력이 인식되었음을 알린다.
- 시스템 전원이 켜지면 시스템 전원 LED가 점등된다.

### 3.7. 외부 명령

- **주기적 상태 전송**: 시스템의 현재 모드, 보안 경고 상태, 온습도/밝기 값을 주기적으로  Broadcast 한다.
- **명령 수신:**
    - **원격 모드 변경**: 외부 시스템으로부터 ‘모드 변경’ 명령을 수신하면 해당 모드로 즉시 변경한다.
    - **원격 경고 해제**: 외부 시스템으로부터 '경고 해제' 명령을 수신하면 보안 경고 상태를 해제하고, 보안 모드는 유지한다.
    - **원격 장치 제어**: 외부 시스템으로부터 ‘장치 제어’와 ‘제어할 장치’, ‘동작’이 담긴 명령을 수신하면 해당 장치의 동작을 제어한다.

---

## **4. Non-Functional Requirements**

1. **성능**: 사용자 입력에 대한 시스템 반응은 과도한 지연 없이 이루어져야 한다. 센서 값 모니터링 주기는 1000ms로 한다.
2. **신뢰성**: 시스템은 **RTOS** 기반으로 구현되어야 하며, 특정 기능이 다른 기능의 실행을 방해해서는 안 된다. 각 주요 기능은 별도의 Task로 관리되어야 한다.
3. **사용성**: 디스플레이에 표시되는 정보는 사용자가 시스템의 현재 상태를 직관적으로 이해할 수 있도록 명확해야 한다.
4. **확장성**: 각 센서 및 액추에이터의 드라이버 코드는 모듈화되어, 향후 다른 종류의 센서를 추가하거나 교체하기 용이한 구조여야 한다.
